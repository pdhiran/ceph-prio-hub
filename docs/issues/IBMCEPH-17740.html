Root Cause Analysis
OSD segfaults every ~12 hours in ScrubQueue::collect_ripe_jobs() on the safe_timer thread, caused by a race condition between PG worker threads mutating scrub job schedules and the safe_timer thread sorting them.
ROOT CAUSE: Race condition in the OSD scrub scheduling code. The safe_timer thread periodically calls OSD::tick_without_osd_lock() -> OsdScrub::initiate_scrub() -> ScrubQueue::ready_to_scrub() -> ScrubQueue::collect_ripe_jobs(). Inside collect_ripe_jobs(), std::sort() iterates over the scrub job vector. Concurrently, PG worker threads call update_job() and delay_on_failure() which mutate scrub job schedule timestamps in the same vector without holding jobs_lock. When std::sort() encounters a job whose comparison key has been mutated mid-sort, the comparison becomes inconsistent, violating the strict weak ordering requirement, leading to undefined behavior and ultimately a segfault. The upstream fix (PR #70762, Tracker Bug #78874) enforces jobs_lock across all scrub schedule update paths and introduces update_job_without_lock() to prevent deadlocks.
