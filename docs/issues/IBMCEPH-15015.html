Root Cause Analysis
Ceph container images contain private SSH key (id_rsa_drop.ceph.com) triggering compliance scan failures.
ROOT CAUSE: The file /usr/share/ceph/id_rsa_drop.ceph.com is a legacy SSH private key originally used by the 'ceph-post-file' utility, which allowed users to upload crash dumps and logs to drop.ceph.com via SFTP. The host was configured to only allow sftp file uploads (no shell access). David Galloway confirmed the service the key connects to is no longer in active use. The key is packaged into all Ceph container images (rook-ceph-operator, cephcsi-rhel9, ceph, ocs-metrics-exporter-rhel9) and triggers Twistlock compliance scan failures for private key presence. While not an actual security vulnerability (the key only provides write-only sftp access to a defunct service), it causes compliance failures for customers with strict image scanning policies.
KEY EVIDENCE
  • Twistlock scan report flagging /usr/share/ceph/id_rsa_drop.ceph.com in 5 container images
  • David Galloway confirmed: key is for ceph-post-file SFTP upload to drop.ceph.com (now defunct)
  • Marcus Watts: 'It's certainly not a security exposure for a random ceph install'
  • Sage McTaggart: 'This is embarrassing for Ceph but has very minimal impact on our actual severity'
  • The service is being replaced with HTTPS POST by EOY
FIX STATUS: New/Open. Low priority per security team. Sage McTaggart plans to submit upstream PR to remove the key. Target: 9.2 or 10.0. No upstream tracker created yet. Marcus Watts provided downstream PR instructions in latest comment.
