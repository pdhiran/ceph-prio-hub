Root Cause Analysis
`ceph orch hardware status` fails with TypeError because node-proxy cache receives malformed data (non-dict values) from Redfish when hardware reports null health status.
ROOT CAUSE
The is_error() and is_unknown() functions in inventory.py assume a strict nested dictionary structure (status['status']['health']). When Redfish API returns null values for Health fields (e.g., "Health": null, "HealthRollup": null) on certain Dell hardware controllers (AHCI embedded controllers with no drives), the node-proxy cache stores malformed entries. Attempting status['status']['health'].lower() on a non-dict or None value raises TypeError: string indices must be integers.
KEY EVIDENCE
  • Traceback: inventory.py:1906 is_error -&gt; status[&#x27;status&#x27;][&#x27;health&#x27;].lower() -> TypeError
  • Dell Redfish data shows: &quot;Status&quot;: {&quot;Health&quot;: null, &quot;HealthRollup&quot;: null, &quot;State&quot;: &quot;Enabled&quot;}
  • Fix already in 9.1 via PR #74749 (commit ce360a4a5f67): get_node_proxy_status_value() centralizes safe access
  • Guillaume Abrioux: feature developed/tested on VMs, limited hardware validation
  • Backport to 8.1 deemed unlikely due to merge conflicts
FIX STATUS
