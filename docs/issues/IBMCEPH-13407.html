Root Cause Analysis
### Root Cause Analysis:
SUMMARY: Dashboard crashes with HTTP 500 due to malformed 'refs' data in progress events causing dict() ValueError
ROOT CAUSE: The dashboard's progress.py module crashes when processing finished progress events that contain malformed 'refs' data. The code at line 52 does: 'metadata': dict(event.get('refs', {})) -- when refs is a simple list like ['mds', 'clone'] instead of a list-of-pairs like [['pool', 23]], dict() raises ValueError because each element has length != 2. The specific trigger is CephFS clone operations which emit progress events with refs=['mds', 'clone']. This crashes the /api/summary endpoint, making all dashboard pages that call it return HTTP 500. Workaround: 'ceph progress clear' to remove problematic progress events.
KEY EVIDENCE:
- Traceback: ValueError: dictionary update sequence element #0 has length 3; 2 is required
- At: progress.py line 52: dict(event.get('refs', {}))
- Trigger event: refs=['mds', 'clone'] (from CephFS clone operation)
- Fix: validate refs type before dict() conversion
- Upstream PR raised, downstream commit 5a09367ba311
FIX STATUS: Fixed. Upstream PR merged. Downstream PR committed (5a09367ba311). Verified in 20.2.2-124. Backport to 9.1z2 planned.
