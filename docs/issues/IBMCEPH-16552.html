Root Cause Analysis
Cephadm module crashes with 'dictionary changed size during iteration' due to race condition between spec store iteration and concurrent CLI mutations.
ROOT CAUSE
The cephadm serve loop's _find_orphans_to_remove() function accesses self.mgr.spec_store.active_specs which builds a dict comprehension from self._specs.items(). If a concurrent CLI command (e.g., ceph orch apply -i spec.yaml or ceph orch rm) modifies the _specs dictionary while the serve loop is iterating, Python raises RuntimeError: dictionary changed size during iteration. The race window is microseconds wide. The fix wraps the iteration in a list() constructor to iterate over a snapshot copy.
KEY EVIDENCE
  • Traceback: inventory.py:460 active_specs -&gt; return {k: v for k, v in self._specs.items() if k not in self.spec_deleted} -> RuntimeError
  • Timothy Nguyen RCA: "the stored specs was changed during the serve loop's orphan daemon clean up, so likely a cli command...was ran"
  • Customer (IBM Cloud Acadia): intermittent HEALTH_WARN, resolved by ceph mgr fail
  • Fix PR: https://github.com/ceph/ceph/pull/70411 (wraps dict iteration in list())
  • QE unable to reproduce despite multiple attempts with concurrent orch apply/rm loops
  • Impact: control plane only, data path unaffected
FIX STATUS
  • Status: Post (fix merged to main, targeting 10.0)
  • Workaround: ceph mgr fail to restart the cephadm module
  • PR: #70411 (ceph:main)
