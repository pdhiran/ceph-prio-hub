Root Cause Analysis
RGW returns HTTP 200 with correct Content-Length but never sends the response body when a GET request includes an Origin header on a bucket without CORS configuration, causing client to hang until timeout.
ROOT CAUSE: The bug is in the RGW CORS handling during S3 GET object operations. When both global CORS and bucket CORS are unconfigured, the code path executes op_ret = std::min(temp_op_ret, read_global_cors_ret). read_global_cors() returns -22 (EINVAL) when no global CORS exists, and read_bucket_cors() returns 0 when no bucket CORS exists. std::min(0, -22) yields -22, which is stored in op_ret. Later, in the send_data phase, the condition if (get_data && !op_ret) evaluates !(-22) as false (since -22 is non-zero/truthy in C++), so dump_body() is never called. The HTTP headers (including a correct Content-Length) have already been sent, but the body is never written, causing the client to hang. This is a regression introduced between 20.1.0-221 and 20.2.1-294.
