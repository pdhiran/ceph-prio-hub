Root Cause Analysis
Windows client cannot connect to Ceph SMB share due to Samba container image version mismatch - customer using v0.5 image with 8.1z3 cluster.
ROOT CAUSE: Customer was using quay mirroring repo with samba-server-rhel9:v0.5 container image while the cluster was on IBM Ceph v8.1z3. The version mismatch caused the ceph_new VFS module to fail connecting to the CephFS backend, producing 'No buffer space available' and 'Transport endpoint is not connected' errors. The Samba container's libcephfs client was incompatible with the cluster version, preventing CephFS mount from the container.
KEY EVIDENCE
  • Error: 'make_connection_snum: does not exist or permission denied - Error was No buffer space available'
  • Error: 'vfs_ceph_disconnect: failed to unmount: Transport endpoint is not connected'
  • Customer using samba-server-rhel9:v0.5 with IBM Ceph 8.1z3 cluster
  • Fix: ceph config set mgr mgr/cephadm/container_image_samba cp.icr.io/cp/ibm-ceph/samba-server-rhel9:v8.1
  • CTDB connection failures also present (cosmetic, separate from root cause)
FIX STATUS: Closed - not a bug. Resolution was changing SMB container image version to match cluster version (:v8.1). Customer confirmed working after image change.
