Root Cause Analysis
MDS restart under heavy EC workload causes OSD crash loop due to BlueStore clonerange2 error on EC pool objects.
ROOT CAUSE: The initial failure is a BlueStore error during _txc_add_transaction: an EINVAL (error 22) on a 'clonerange2' operation (op 30) for an EC-coded object. BlueStore does not support clonerange2 for EC pools -- this operation is being incorrectly submitted to BlueStore during heavy CephFS workload with EC data pool after MDS restart. The MDS restart triggers client reconnection storms and cap recovery, which creates a burst of write operations. The clonerange2 failure corrupts an object, and subsequent read attempts on that object trigger ECCommon::ReadPipeline::complete_read_op and ECCommon::RecoveryBackend::handle_recovery_read_complete assert failures, causing cascade OSD crashes.
KEY EVIDENCE
  • Three distinct crash types: BlueStore _txc_add_transaction abort, ECCommon ReadPipeline assert, ECCommon RecoveryBackend assert
  • Initial error: 'bluestore _txc_add_transaction error (22) Invalid argument not handled on operation 30 (op 1, counting from 0)' -- clonerange2 on EC object
  • 8 OSDs in error state across 4 nodes (grim001-004)
  • Version: 20.1.0-178.el9cp (Tentacle 9.0z2) and also on 20.2.1-216.el9cp
  • Reproducible: Deploy EC 2+2 CephFS data pool, fill to 20%, run 300+ clients with heavy IO for 35+ hours, restart MDS
  • PG_DAMAGED, OBJECT_UNFOUND health warnings observed
