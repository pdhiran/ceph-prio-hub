Root Cause Analysis
ceph-exporter floods logs with 'pid path is empty' warnings because containerized daemons run in foreground (-f) without PID files.
ROOT CAUSE: The ceph-exporter attempts to collect per-daemon process metrics by reading PID files. In containerized deployments, all Ceph daemons run with the -f (foreground) flag, which means no PID file is created. The code at the pid_path check logs 'pid path is empty; process metrics won't be fetched for: <daemon>' at debug level 1 for every daemon, every scrape cycle (~once per minute per daemon). With syslog forwarding enabled, this generates continuous alerts across all nodes. The message is logged at level 1 (user.err in syslog), making it indistinguishable from real errors.
KEY EVIDENCE
  • All daemons run with -f flag: /usr/bin/radosgw -n client.rgw... -f, /usr/bin/ceph-mon... -f, /usr/bin/ceph-osd... -f
  • PID file not created when daemon runs in foreground
  • Affects OSD, MON, RGW, lifecycle daemons on every node
  • Reproduces on 8.1z5, 8.1z7, and 9.9.0.2
  • Upstream tracker exists with stale PR
  • Workaround: rsyslog filter to suppress specific message
  • No workaround for journalctl without code change
FIX STATUS: In progress. Aarti Dhikale investigating. Upstream PR existed but was closed due to inactivity. Workaround: rsyslog filter (cat > /etc/rsyslog.d/ceph-exporter-filter.conf). Fix needs to either lower log level, suppress the message in containerized mode, or find PID via alternative method (e.g., /proc).
