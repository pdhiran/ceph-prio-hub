Root Cause Analysis
cephadm-preflight.yml unconditionally enables firewalld during RHCS 7->8.1 upgrade, causing cluster outage in environments where firewalld is intentionally disabled.
ROOT CAUSE
The cephadm-preflight.yml playbook contains a task that unconditionally starts and enables firewalld on all nodes without checking whether the administrator intentionally disabled it. When firewalld starts with default rules, it blocks inter-node Ceph traffic (MON, OSD, MGR ports), causing a complete cluster network outage. This is a regression from RHCS 7 where the pre-check process did not modify the host firewall state. The fix requires adding a configurable variable (e.g., cephadm_preflight_manage_firewall) to allow skipping firewall management.
KEY EVIDENCE
  • Customer (Swisscom) experienced IPTV streaming disruption during pre-production upgrade
  • Reproduced in lab: nodes with firewalld disabled get it force-enabled by preflight playbook
  • Workaround confirmed by Swati Thombe: set enabled: false in the firewalld task as temporary measure
  • Fix being tracked under IBMCEPH-13852 PR (under review)
  • Reporter suggests: when: cephadm_preflight_manage_firewall | default(true) | bool
FIX STATUS
  • Status: New (PR under review)
  • Workaround: Manually edit cephadm-preflight.yml to add when: false to firewalld task
  • Related: IBMCEPH-13852 (configurable firewalld management)
