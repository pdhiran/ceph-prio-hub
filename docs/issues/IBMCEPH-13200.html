Root Cause Analysis
RGW bucket notification fails with HTTPS push endpoint returning error -2200, due to a combination of DNS resolution failure inside the RGW container and TLS/certificate issues.
ROOT CAUSE: Two separate issues: (1) The HTTPS push endpoint URL uses a long custom domain name with hyphens (e.g., fluentd-http-route-fluentd-listener.apps.dsp01-svc-q.data.bdp.belastingdienst.nl) that could not be resolved from within the RGW container. The curl error 'Couldn't resolve host name' confirms DNS resolution failure inside the container. (2) The push server uses a self-signed certificate, causing TLS verification failures (even with verify-ssl=false, the RGW may still fail on certain certificate chain issues). Lab reproduction showed the issue is specific to certain domain name patterns; simpler domain names work fine. The engineering team could not reproduce with the same long domain name and self-signed cert in all configurations.
KEY EVIDENCE
  • RGW log: 'push entry marker failed. error: -2200 (will retry)'
  • curl error inside container: 'Could not resolve host: fluentd-http-route-fluentd-listener.apps.dsp01-svc-q.data.bdp.belastingdienst.nl'
  • curl from container also shows: 'SSL certificate problem: self-signed certificate in certificate chain'
  • Lab test with simple domain (mydomain.example.com) + self-signed cert works fine
  • Lab test with customer's exact long domain name reproduces TLS issue
  • Workaround: use HTTP endpoint instead of HTTPS
FIX STATUS: Closed as 'insufficient data'. Customer environment specifics (DNS, certificate chain, network) could not be fully replicated. Workaround: use HTTP push endpoint or ensure DNS resolves inside RGW container.

Goal: Reproduce RGW bucket notification failure with HTTPS push endpoint
Environment: IBM Ceph 8.0, multisite cluster
