Root Cause Analysis
### Root Cause Analysis:
SUMMARY: ceph-volume inventory crashes with RuntimeError when thin-provisioned LVM volumes exist on host
ROOT CAUSE: ceph-volume's device inventory code (device.py) tries to resolve all LVM logical volumes including hidden thin pool metadata and data sub-volumes (thinpool_tdata, thinpool_tmeta). These hidden LVs don't have symlinks under /dev/<vgname>/ (they only exist under /dev/mapper/), causing UdevData.__init__() to raise RuntimeError when the path is not found. The fix filters out thin pool metadata and data sub-volumes from the device inventory, since they are internal LVM implementation details and not usable as OSD devices.
KEY EVIDENCE:
- Error: RuntimeError: /dev/test/thinpool_tdata not found
- Stack: device.py _get_device_id -> disk.py UdevData -> RuntimeError
- blkid errors: 'blkid: error: /dev/test/thinpool_tdata: No such file or directory'
- Regression from earlier versions (7.1 showed them but didn't crash)
- Fix: filter thin-provisioned hidden LVs in ceph-volume inventory
- Downstream MR !1651 merged
FIX STATUS: Fixed. Upstream fix by Guillaume Abrioux. Downstream MR !1651 merged. Verified in 19.2.1-354 (8.1z6) by QE. Backported to 8.1z6 and 9.0z2. Closed as part of 9.1 release.
Steps to Reproduce
### Steps to Reproduce:
Goal: Reproduce ceph-volume inventory crash with thin-provisioned LVs
Environment: IBM Ceph 8.x or 9.x (pre-fix)
1. dd if=/dev/zero of=/disk.img bs=1M count=1024
2. losetup -f --show /disk.img
3. vgcreate test /dev/loop0
4. lvcreate -L 900M -T test/thinpool
5. cephadm ceph-volume inventory -- crashes with RuntimeError
DIAGNOSTIC COMMANDS:
- ls -la /dev/test/ (only thinpool symlink, no thinpool_tdata)
- ls -la /dev/mapper/test* (all 3 symlinks present)
- lvs -a (shows hidden _tdata and _tmeta volumes)
