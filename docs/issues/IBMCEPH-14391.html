Root Cause Analysis
RGW multisite secondary promotion failed due to operator error (wrong realm) and residual metadata artifacts -- not a bug.
ROOT CAUSE: Customer promoted a secondary zone to master using 'radosgw-admin zone modify --rgw-zone second-site-zone --master --default' but forgot to specify '--rgw-realm=multisite-realm', causing the promotion to apply to the wrong realm. This corrupted the multisite sync metadata. Subsequent attempts to rebuild the multisite setup failed with 'No such file or directory' errors because residual artifacts from the incorrect promotion persisted in RADOS objects (rgw.meta pool). The 'period get' output showed empty strings in sync_status array, which are normal -- each element is a metadata sync shard marker, and empty entries mean no sync activity on those shards.
KEY EVIDENCE
  • Customer omitted --rgw-realm flag during zone promotion
  • RGW log: 'cache get: name=site.rgw.meta+root+sync.np hit: (negative entry)' -> missing sync metadata object
  • sync_status array with empty entries is normal (inactive shards)
  • Shilpa Jagannath confirmed: 'empty entries mean there wasn't any sync activity on those shards'
  • Support team successfully set up fresh multisite following correct procedure
FIX STATUS: Closed as 'not a bug'. Resolution was operator error. The support team provided step-by-step multisite setup instructions that work correctly.
