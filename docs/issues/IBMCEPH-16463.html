Root Cause Analysis
SMB small-file sync is extremely slow (~100 files/min) because CephFS subvolume has case-sensitivity enabled, forcing Samba to issue massive readdir calls for case-insensitive lookups.
ROOT CAUSE
SMB protocol operates with case-insensitive semantics, but the CephFS subvolume was created with casesensitive: true (default). When Samba needs to open/create a file on a case-insensitive share backed by a case-sensitive filesystem, it must enumerate the entire directory to check for case-colliding names. This caused ~95 readdir syscalls per smb2_create operation. With millions of files, the stat cache (which showed 0 hits) was ineffective, making each file creation trigger thousands of readdir operations. Setting --casesensitive=0 on the subvolume reduced readdir calls from 8M to 362 in a 5-minute window and improved throughput from ~0.6 files/sec to ~120 files/sec.
KEY EVIDENCE
  • Samba profile: smb2_create: 85,031 / syscall_readdir: 8,094,073 = ~95 readdir per create (case-sensitive)
  • After fix: smb2_create: 190,320 / syscall_readdir: 362 = ~0.002 readdir per create (case-insensitive)
  • ceph fs subvolume info confirmed: &quot;casesensitive&quot;: true
  • Anoop C S: "the CephFS subvolume must have case sensitivity disabled"
  • Direct CephFS: 0.2s for 100 create/delete; SMB: 5.6s = 28x slower via SMB
  • Customer confirmed: performance improvement was "very large" after fix
