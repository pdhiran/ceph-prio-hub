Root Cause Analysis
MDS crash with FAILED ceph_assert(_raw) during dump_tree admin socket command on IBM Ceph 8.1z5, same signature as IBMCEPH-12883 but fix reportedly already present.
ROOT CAUSE: Same mechanism as IBMCEPH-12883 -- MDCache::dump_tree() encounters an inode with an empty xattr buffer (nullptr _raw pointer) and crashes when calling c_str(). In this specific case, detailed log analysis by Manya Dogra revealed the MDS main thread had been frozen for ~3 minutes due to enormous journal events (2-2.5MB each, caused by 9.8M caps across clients). The dump_tree command was running on the admin_socket thread independently. When the pod received SIGTERM, the admin_socket thread was mid-traversal and hit the null buffer 1 second later. The fix commits for this assert are reportedly present in 8.1z5, but the crash still occurred -- engineering needs core dump to investigate why.
