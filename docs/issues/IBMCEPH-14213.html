Root Cause Analysis
RGW crashes with segfault in tcmalloc during multi-object delete operations on multisite cluster upgraded from Ceph 8 to Ceph 9, related to heap corruption during concurrent delete operations.
ROOT CAUSE
During bulk object deletion (using s5cmd with 64+ workers) on a multisite cluster upgraded from Ceph 8 to 9, the RGW process crashes with SIGSEGV in tcmalloc's ThreadCache::ReleaseToCentralCache(). The crash occurs in the io_context_pool thread, suggesting heap corruption during concurrent I/O processing. A hotfix build (20.1.0-185.0.hotfix.IBMCEPH14213) was provided but showed a different crash in the same tcmalloc path. The underlying issue appears to be a use-after-free or double-free in the RGW multisite delete path that corrupts tcmalloc's internal structures.
KEY EVIDENCE
  • Crash: tcmalloc::ThreadCache::ReleaseToCentralCache() -&gt; SIGSEGV in io_context_pool thread
  • Also seen: std::bad_alloc crash during same delete workload
  • Trigger: s5cmd --numworkers 64 rm s3://&lt;bucket&gt;/* (bulk delete 50K objects)
  • Version: 19.2.1-245.el9cp (upgraded from Ceph 8 to 9)
  • Hotfix delivered but showed different crash; documented as known issue
  • Fix verified in 9.1z2 build (20.2.1-367.el9cp)
FIX STATUS
