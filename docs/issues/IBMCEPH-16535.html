Root Cause Analysis
After upgrading from IBM Ceph 8.1 to 9.1, cephadm normalizes hostnames to lowercase in its inventory but service placement specs still reference uppercase names, causing all service apply operations to fail.
ROOT CAUSE
A commit in Ceph Tentacle (9.x) introduced hostname normalization to lowercase in the cephadm host inventory. However, the persisted service placement specifications (which reference hosts by name) were not migrated to match the new lowercase names. This creates a mismatch: ceph orch host ls shows lowercase hostnames, but ceph orch ls placement and ceph orch host rm <lowercase> fails with 'host does not exist' because the internal lookup uses case-sensitive comparison between the old uppercase specs and new lowercase inventory.
KEY EVIDENCE
  • Before upgrade: ceph orch host ls shows MULTI80-SITE1 (uppercase)
  • After upgrade: ceph orch host ls shows multi80-site1 (lowercase)
  • ceph orch host rm multi80-site3 -> 'host multi80-site3 does not exist'
  • HEALTH_WARN: Failed to apply 12 services
  • Fix PR by SHUBHA JAIN: hostname normalization + spec migration
  • Verified fixed in 9.9.2 build (20.2.2-181.el10cp)
FIX STATUS
  • Status: Verified
  • Fix: PR merged to 9.2 branch with spec migration logic
  • 9.1z2 MR: https://gitlab.cee.redhat.com/ceph/ceph/-/merge_requests/2166
