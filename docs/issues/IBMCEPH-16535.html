Root Cause Analysis
Cephadm normalizes hostnames to lowercase during 8.1 -> 9.x upgrade, breaking service placement and host management for clusters using uppercase hostnames.
ROOT CAUSE
  • During the upgrade from IBM Ceph 8.1 to 9.x, cephadm's host inventory migration normalizes all hostnames to lowercase
  • However, existing metadata stores (MON map, CRUSH map, service placement specs, daemon IDs) retain the original uppercase hostnames
  • This creates a split-brain state: cephadm inventory says "multi80-site1" but MON/CRUSH says "MULTI80-SITE1"
  • Service placement fails because cephadm tries to match lowercase inventory against uppercase placement specs
  • Host management commands fail: ceph orch host rm multi80-site1 says "host does not exist" because the canonical name is still uppercase
FIX STATUS
  • Upstream PR: https://github.com/ceph/ceph/pull/70346
  • Engineering provided iterative fixes: inventory normalization, case-insensitive host matching, placement spec migration
  • Remaining cosmetic: ceph osd tree, ceph mon stat, ceph quorum_status still show uppercase (from CRUSH/MON metadata, not cephadm)
  • OSD redeployment correctly uses existing uppercase CRUSH bucket (no duplicate lowercase bucket created)
  • Status: Verified -- cephadm scope is fixed; CRUSH/MON display is cosmetic, not functional
Steps to Reproduce
Goal: Reproduce the hostname case normalization regression during IBM Ceph 8.1 -> 9.x upgrade on a cluster with uppercase hostnames.
  • 1. Deploy IBM Ceph 8.1 cluster with uppercase hostnames -- cephadm bootstrap --mon-ip=&lt;ip&gt; on a host named e.g. MULTI80-SITE1
  • 2. Add additional hosts with uppercase names -- ceph orch host add MULTI80-SITE2 &lt;ip&gt;
  • 3. Deploy services (mon, mgr, osd, rgw) -- ceph orch apply mon &quot;MULTI80-SITE1;MULTI80-SITE2;MULTI80-SITE3&quot;
  • 4. Verify pre-upgrade state -- ceph orch host ls should show uppercase hostnames
  • 5. Perform upgrade to IBM Ceph 9.x -- ceph orch upgrade start --image &lt;9.x-image&gt;
  • 6. After upgrade completes, check host inventory -- ceph orch host ls now shows lowercase
  • 7. Verify service placement failure -- ceph -s shows HEALTH_WARN with "Failed to apply N service(s)"
  • 8. Attempt host management -- ceph orch host rm multi80-site1 returns "host does not exist"
  • 9. Check MON map for case mismatch -- ceph mon dump still shows uppercase MON names
