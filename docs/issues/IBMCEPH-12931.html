Root Cause Analysis
Git clone fails with 'permission denied' on NFS exports with no_root_squash due to NFS-Ganesha file reopen access mask bug.
ROOT CAUSE: When git clone reopens a temporary pack file in read-only mode after initially opening it read-write, NFS-Ganesha incorrectly merges the old access mask (which includes write permission) with the new read-only open request. The permission check then fails because the combined mask requests write access on a read-only reopen. A second bug in the CEPH FSAL causes fsync permission errors during write operations. Both issues are in the NFS-Ganesha access permission enforcement path during file reopen operations.
KEY EVIDENCE
  • Error: "fatal: could not open '.git/objects/pack/tmp_pack_XXXXX' for reading: Permission denied"
  • Second error: "fatal: fsync error on '.git/objects/pack/tmp_pack_XXXXX': Permission denied"
  • RCA from Sachin Punadikar: reopen request incorrectly adds old access mask flags to new access mask during permission check
  • Reproduced by QE (Aarti Dhikale) on RHEL 9.7 with no_root_squash export
  • Fix commits: https://gitlab.cee.redhat.com/ceph/nfs-ganesha/-/commit/53e5f616 (reopen fix) and https://gitlab.cee.redhat.com/ceph/nfs-ganesha/-/commit/fd2a3c16 (CEPH FSAL fsync fix)
FIX STATUS: Fixed in 8.1z5 (nfs-ganesha-6.5-34). Verified by QE on 19.2.1-331.el9cp. Closed as part of 8.1z5 release. Clone IBMCEPH-13159 tracked the 9.0 fix.
