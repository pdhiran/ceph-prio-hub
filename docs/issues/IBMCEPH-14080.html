Root Cause Analysis
MGR crashes with KeyError during maintenance mode exit because cephadm cache.get_hosts() returns a host not present in inventory._inventory.
ROOT CAUSE: After upgrading to 7.1z9, some OSD hosts lack the 'osd' label despite running OSD daemons. When such a host exits maintenance mode, the cephadm serve loop's refresh() function iterates over cache.get_hosts() and checks inventory._inventory[host].get('status') -- but the host is not in the inventory dict, causing a Python KeyError that crashes the MGR module. The inconsistency between cache and inventory occurs intermittently after reboot, where the first maintenance exit attempt fails while the second succeeds. The exact trigger for the cache/inventory desynchronization is unknown and not reproducible in lab.
KEY EVIDENCE
  • Crash: KeyError: 's-3qswg04.sys.az1.cust.atl.wd' at serve.py:252
  • Stack: inventory._inventory[host].get('status', '').lower() == 'maintenance'
  • Hosts lack 'osd' label but have running OSD daemons
  • First maintenance exit attempt fails, second succeeds
  • Not reproducible in lab
  • Similar KeyError issues seen in IBMCEPH-related trackers after host removal + upgrade
FIX STATUS: Closed as 'not a bug'. Not reproducible. Customer will reopen if issue recurs with requested inventory captures.
