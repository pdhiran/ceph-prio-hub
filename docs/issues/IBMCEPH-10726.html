Root Cause Analysis
RFE to add NO_CRUSH_TUNABLES health warning when CRUSH tunables profile is 'unknown' or unset.
ROOT CAUSE: This is a feature request (RFE), not a bug. Clusters with history of manual CRUSH map editing or long upgrade paths (Luminous->Pacific->Quincy) can end up with CRUSH tunables profile='unknown' and both optimal_tunables=0 and legacy_tunables=0. This state correlates with undersized/inactive PGs. Currently Ceph has OLD_CRUSH_TUNABLES check but no check for missing/unknown tunables profile.
KEY EVIDENCE
  • Profile: 'unknown', optimal_tunables: 0, legacy_tunables: 0
  • minimum_required_version: 'jewel'
  • Seen on clusters with long upgrade history (Luminous->Nautilus->Pacific->Quincy)
  • Both upstream (Reef install) and downstream (5.3/Pacific) instances observed
  • Brad Hubbard accepted and self-assigned the RFE
FIX STATUS: Assigned to Brad Hubbard. Targeted for 8.2. RFE accepted but not yet implemented.
Steps to Reproduce
Goal: Create a cluster with unknown CRUSH tunables profile to validate future health warning
Environment: Any Ceph version with crushtool available
  • 1. Deploy cluster normally -- intent: baseline
  • 2. ceph osd getcrushmap -o /tmp/crushmap.bin -- intent: extract CRUSH map
  • 3. crushtool -d /tmp/crushmap.bin -o /tmp/crushmap.txt -- intent: decompile
  • 4. Manually edit tunables to invalid combination -- intent: create unknown profile state
  • 5. crushtool -c /tmp/crushmap.txt -o /tmp/crushmap_modified.bin -- intent: recompile
  • 6. ceph osd setcrushmap -i /tmp/crushmap_modified.bin -- intent: apply modified map
  • 7. ceph health detail -- intent: verify NO_CRUSH_TUNABLES warning (once implemented)
DIAGNOSTIC COMMANDS
  • ceph osd crush show-tunables
  • ceph report | jq '.crushmap.tunables'
  • ceph osd crush tunables optimal
