Root Cause Analysis
IBM Container Registry (cp.icr.io) returns WWW-Authenticate headers with spaces after commas, causing cephadm's OAuth token request to fail with HTTP 400 when checking for upgrades.
ROOT CAUSE
The cephadm registry.py module parses WWW-Authenticate response headers by splitting on commas but does not strip leading/trailing whitespace from the resulting key-value pairs. IBM Container Registry (cp.icr.io) returns headers formatted as: Bearer realm="...", service="registry", scope="repository:..." — note the space after each comma. The parser produces parameter keys like service and scope (with leading space), which get URL-encoded into the OAuth token request. The registry rejects the malformed URL with HTTP 400 Bad Request. This only affects the ceph orch upgrade ls command (and the GUI upgrade-check flow that calls it); CLI-based upgrades using ceph orch upgrade start --image <image> bypass this code path entirely.
