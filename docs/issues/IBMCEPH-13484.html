Root Cause Analysis
SMB share permissions show SID values instead of AD group names because the Samba `run` directory permissions (0700) prevent winbindd from resolving SIDs via the named pipe.
ROOT CAUSE
The cephadm-deployed SMB container creates the /var/lib/ceph/<fsid>/<smb-daemon-name>/run directory with permissions 0700 (owner-only). Winbindd, which handles SID-to-name resolution, uses a Unix socket in this directory. When non-root SMB client processes attempt to communicate with winbindd via this socket, the restrictive permissions prevent access, causing SID resolution failures. As a result, Windows clients see raw SID strings (e.g., S-1-5-21-...) instead of AD group names in the Security tab. A secondary issue was the CTDB sidecar hitting PID limits (2048 per container) causing fork failures, which was mitigated by setting TasksMax=infinity on the systemd unit. The actual root cause fix is chmod 0755 on the run directory, which was confirmed by the customer to resolve the issue.
