Root Cause Analysis
CEPHADM_STRAY_HOST warning after cluster expansion due to cephadm inventory key exceeding mon_config_key_max_entry_size (default 65KB).
ROOT CAUSE: The cephadm inventory data for all hosts is stored in a single MON config-key entry. At large scale (600+ hosts, 21 racks), this entry exceeded the 65KB default limit of mon_config_key_max_entry_size, preventing new host data from being persisted. After MGR failover or restart, hosts whose inventory data wasn't saved appear as CEPHADM_STRAY_HOST with 'daemons not managed by cephadm'. Additionally, setting the config at 'global' scope does not take effect -- it must be set at 'mon' scope. Mixed IPv4/IPv6 host resolution was also observed but not confirmed as contributing factor.
KEY EVIDENCE
  • 55 stray hosts with 528 daemons not managed by cephadm
  • MON log: 'CEPHADM_STRAY_HOST: 55 stray host(s) with 528 daemon(s)'
  • Workaround: ceph config set mon mon_config_key_max_entry_size 1048576
  • ceph config set global ... did NOT work (must use 'mon' scope)
  • After fix + re-add hosts, stray warnings permanent resolved
  • 10K scale testing validated the workaround
  • Patch to split inventory into multiple keys: 9.0 release
  • Default increase to 256K tracked in IBMCEPH-13208
FIX STATUS: Closed as 'not a bug'. Workaround: increase mon_config_key_max_entry_size to 1MB under mon scope. Permanent fix (split inventory) in 9.0. Default increase to 256K (supports ~1200 nodes) in IBMCEPH-13208.
