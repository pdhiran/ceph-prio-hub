Root Cause Analysis
Not a bug -- S3 object lock in COMPLIANCE mode correctly allows delete markers while protecting versioned object data.
ROOT CAUSE: This is expected S3 behavior, not a bug. In COMPLIANCE mode, creating a delete marker (simple DELETE without version-id) is allowed -- it hides the current version but does not delete the underlying object data. The actual versioned object remains protected and cannot be permanently deleted (DELETE with version-id returns AccessDenied). The customer confused delete marker creation with actual object deletion. The objects remained accessible via their version IDs.
KEY EVIDENCE
  • 'aws s3 rm' succeeded (creates delete marker) but versioned objects still present in list-object-versions
  • Attempting 'aws s3api delete-object --version-id' correctly returns 'AccessDenied: forbidden by object lock'
  • Verified on 8.1z5 (19.2.1-329.el9cp) -- same expected behavior
  • Closed as 'not a bug' after confirming with RGW engineering
FIX STATUS: Closed as 'not a bug'. Expected S3 behavior documented in AWS S3 specification.

Goal: Verify S3 object lock COMPLIANCE mode correctly protects versioned objects while allowing delete markers

  • 2. aws s3api put-object-lock-configuration --bucket worm-bucket --object-lock-configuration '{"ObjectLockEnabled":"Enabled","Rule":{"DefaultRetention":{"Mode":"COMPLIANCE","Days":10}}}' -- intent: set compliance mode

  • 4. aws s3 rm s3://worm-bucket/<key> -- intent: verify delete marker is created (expected: succeeds)
