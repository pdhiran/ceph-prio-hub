Root Cause Analysis
Package installation via microdnf fails with 403 error inside IBM Ceph 9.x container images built via IBM SPS pipeline.
ROOT CAUSE: IBM Ceph container images built via IBM SPS (Software Pipeline System) do not include proper RHEL entitlement/subscription configuration, causing dnf/microdnf to receive HTTP 403 when accessing cdn.redhat.com repos (appstream, codeready-builder). Images built via RH OSBS (older 8.1 images) work because they inherit RHEL entitlements. The subscription-manager is also absent from IBM-built containers ('command not found'). Justin Caratzas confirmed: 'The working example (8.1) was built via RH OSBS, while the latter was built via IBM SPS...We'll make changes to make the containers built via SPS be able to install packages via microdnf.'
KEY EVIDENCE
  • Error: 'Status code: 403 for https://cdn.redhat.com/content/dist/rhel9/9/x86_64/codeready-builder/os/repodata/repomd.xml'
  • IBM 8.1 image (cp.icr.io/cp/ibm-ceph/ceph-8-rhel9:8-175) built via OSBS -- works
  • IBM 9.0z2 image (cp.icr.io/cp/ibm-ceph/ceph-9-rhel9:v9.0-13392) built via SPS -- fails
  • subscription-manager: command not found inside container
  • Fix PRs: ceph-pipeline-configs/pull/311, ibm-ceph-container/pull/40
  • Test image available: cp.stg.icr.io/cp/ibm-ceph/ceph-9-rhel9:v9.1-IBMCEPH-17252
FIX STATUS: In progress. CI and container changes submitted (PRs linked). Test image available for validation. Expected to fix all release streams going forward.
