Root Cause Analysis
Upgrade from RHCS 6.1z9 to 8.1z1 fails because custom alertmanager.yml template uses 'default_webhook_urls' variable renamed to 'webhook_urls' in 8.x.
ROOT CAUSE: A code change in Ceph 8.x (commit 42129dd6) renamed the Jinja2 template variable 'default_webhook_urls' to 'webhook_urls' in the alertmanager configuration generation. Customers with custom alertmanager.yml templates (stored in config-key mgr/cephadm/services/alertmanager/alertmanager.yml) referencing the old variable name hit a Jinja2 UndefinedError during upgrade, blocking the alertmanager daemon redeploy and pausing the entire upgrade at 83/95 daemons. The commit claims backward compatibility was maintained, but it does not function during cross-major-version upgrades.
KEY EVIDENCE
  • Error: jinja2.exceptions.UndefinedError: 'default_webhook_urls' is undefined
  • Traceback in cephadm/services/monitoring.py:353 generate_config()
  • Upgrade progress: 83/95 daemons upgraded, paused at alertmanager
  • Workaround: replace 'default_webhook_urls' with 'webhook_urls' in custom template, then 'ceph orch reconfig alertmanager'
  • Documented as known issue in 9.0z2 and 8.1z6 release notes
FIX STATUS: Closed. Documented as known issue in release notes. Pre-upgrade action required: update custom alertmanager templates before upgrading from 6.x to 8.x.
Steps to Reproduce
Goal: Reproduce upgrade failure due to custom alertmanager.yml with legacy variable names
