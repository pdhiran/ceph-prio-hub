Root Cause Analysis
RFE to scale Ceph clusters beyond 65 PiB limit caused by CRUSH weight 16.16 fixed-point format capping root weight at 65535.
ROOT CAUSE: CRUSH represents weights using a 16.16 fixed-point format where the maximum bucket weight is capped at 65535.0, limiting total cluster capacity to approximately 65.5 PiB. Customer (Apple) needs to scale clusters to ~150 PiB each with 10,836 OSDs. The upstream fix (PR#64055, tracker#71763) introduces osd_crush_scaling_factor to scale down weights proportionally. A manual workaround exists: divide all CRUSH weights by a factor (e.g., 10) via crushmap export/awk/reimport.
KEY EVIDENCE
  • Customer needs 150 PiB per cluster with 10,836 OSDs
  • QE (Pawan Dhiran) validated the manual workaround procedure including corrected awk command, multi-iteration scale up/down, host addition with osd_crush_initial_weight
  • Original awk command in comment#5 had a bug causing duplicate entries; corrected to: awk &#x27;/^\s*item .* weight [0-9.]+$/ { $NF = $NF / 10 } { print }&#x27;
  • New OSDs get weight 0.00139 vs expected 0.00145 (~4% variance) despite setting osd_crush_initial_weight=0.00145
  • Upstream PR discussed at CDS Vampire RADOS, planned for merge to main (10.0/Umbrella)
FIX STATUS: Upstream PR#64055 will merge to main soon. Risk concern: modifies OSDMap encoding. No backport planned for older releases since workaround is available. Engineering dubious about risk-to-gain ratio for backport.
Steps to Reproduce
Goal: Validate CRUSH weight scaling workaround for clusters exceeding 65 PiB
Environment: IBM Ceph 8.1+ or 9.x, any cluster size (can simulate with small drives)
  • 1. Export crushmap: ceph osd getcrushmap -o crushmap.old.bin -- intent: backup current state
  • 2. Decompile: crushtool -d crushmap.old.bin -o crushmap.old.txt -- intent: get editable text
  • 3. Divide weights by 10: awk &#x27;/^\s*item .* weight [0-9.]+$/ { $NF = $NF / 10 } { print }&#x27; crushmap.old.txt &gt; crushmap.new.txt -- intent: scale down weights
  • 4. Compile: crushtool -c crushmap.new.txt -o crushmap.new.bin -- intent: validate syntax
  • 5. Set norebalance: ceph osd set norebalance -- intent: prevent PG movement
  • 6. Inject: ceph osd setcrushmap -i crushmap.new.bin -- intent: apply new weights
  • 7. Verify: ceph osd df tree and ceph -s -- intent: confirm HEALTH_OK and correct weights
  • 8. Set ceph config set osd osd_crush_initial_weight &lt;scaled_value&gt; and add new OSD -- intent: test new OSD addition
