Root Cause Analysis
RFE to support multiple client NQNs in a single nvmeof-cli host add command - implemented by separating NQNs with spaces (not commas or quotes).
ROOT CAUSE: The nvmeof-cli originally only accepted a single host NQN per host add command. The fix (PR#817 on ceph-nvmeof) enables passing multiple NQNs as space-separated arguments WITHOUT quotes. Using commas or enclosing in quotes causes the entire string to be treated as a single NQN, failing UUID validation. The confusion arose from unclear documentation and non-intuitive CLI behavior.
KEY EVIDENCE
  • Correct syntax: host add --subsystem &lt;nqn&gt; --host-nqn nqn1 nqn2 nqn3 (space-separated, no quotes)
  • Incorrect: --host-nqn &quot;nqn1, nqn2&quot; or --host-nqn &quot;nqn1 nqn2&quot; (quotes combine into single arg)
  • Fix available in nvmeof 1.3.3+ (IBM Ceph 8.0z2)
  • Limitation: cannot use multiple NQNs when PSK keys are involved
  • Doc update tracked via ISCE-1802
FIX STATUS: Fixed and verified in 8.0z2. Closed. Documentation update tracked in ISCE-1802.

Goal: Verify multiple NQN addition in single host add command

DIAGNOSTIC COMMANDS
