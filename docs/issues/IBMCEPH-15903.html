Root Cause Analysis
Dynamic resharding not triggered for versioned buckets because the 'resharding' feature was never enabled in the zonegroup configuration (pre-dates feature introduction).
ROOT CAUSE
The enabled_features field in the zonegroup configuration was introduced in Ceph Pacific (5.x). For clusters created on earlier releases, this field is NOT automatically populated during upgrades -- it remains empty. The customer's cluster was originally created before this feature existed, so radosgw-admin zonegroup get showed "enabled_features": []. Without the 'resharding' feature enabled in the zonegroup, dynamic resharding cannot be triggered regardless of object count. Additionally, reshard locks were held by other RGW daemons, complicating diagnosis.
KEY EVIDENCE
  • radosgw-admin zonegroup get | grep enabled_features -> &quot;enabled_features&quot;: []
  • Swati Thombe: "The enabled_features field was introduced in Ceph Pacific. For clusters created on earlier releases, this field is not automatically populated during upgrades"
  • After customer enabled resharding feature in zonegroup: buckets resharded successfully and large OMAP warning cleared
  • 34 RGW daemons with reshard lock contention visible in logs
FIX STATUS
  • Status: Closed (Done)
  • Resolution: Customer enabled 'resharding' feature in zonegroup configuration
  • No code fix needed -- documentation/upgrade gap
