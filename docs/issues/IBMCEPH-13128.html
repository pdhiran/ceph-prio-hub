Root Cause Analysis
MON config file takes precedence over config-db for public_network after cluster expansion, causing OSD_UNREACHABLE for 576 OSDs.
ROOT CAUSE: After expanding from 18 to 21 racks (600 OSDs), the MON daemon reads public_network from /var/lib/ceph/<fsid>/mon.<monid>/config which is created during initial deployment and overwritten during upgrades. This file takes precedence over the config-db values set via 'ceph config set'. The new subnets (17.155.208.32/27, 17.155.212.96/27, 17.155.213.96/27) added via config-db were not reflected in the MON config file, so the MON flagged OSDs on those subnets as unreachable. Additionally, cephadm's reconfig+restart scheduling has a race: issuing restart after reconfig is skipped ('skipping restarting, cause reconfig already scheduled'), requiring a separate systemctl restart to force the config reload.
KEY EVIDENCE
  • MON logs show 'address v1:17.155.208.37:6833 is not in networks' listing only original 18 CIDRs
  • ceph config dump showed all 21 CIDRs correctly in global/mon/osd/mgr scopes
  • cat /var/lib/ceph/<fsid>/mon.<monid>/config showed only 18 CIDRs before reconfig
  • After 'ceph orch daemon reconfig' + 'systemctl restart <mon.service>', issue resolved
  • Cephadm log: 'skipping restarting mon.cephnode1156, cause reconfig already scheduled'
FIX STATUS: Workaround applied (reconfig + systemctl restart each MON). No code fix for the precedence issue. Bug still open (status: new).
