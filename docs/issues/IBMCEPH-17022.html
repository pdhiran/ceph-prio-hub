Root Cause Analysis
False-positive MON_NETSPLIT health warning in stretch cluster after upgrade to 8.1z6, caused by known monitor connection scoring defect.
ROOT CAUSE: Post-upgrade to IBM Ceph 8.1z6 (19.2.1-366.el9cp), the cluster reports MON_NETSPLIT warnings despite healthy quorum and verified network connectivity (ping/nc tests pass). The issue is a monitor connection scoring defect where peer_score reports 0 and peer_alive reports false between affected monitor pairs, even though actual network connectivity exists. This is the known false-positive MON_NETSPLIT defect tracked under IBMCEPH-13109 (DFBUGS-8015). The fix is not present in the 8.1z6 code stream. Restarting the affected monitor temporarily clears the warning but the issue recurs between multiple monitor pairs.
KEY EVIDENCE
  • Stretch cluster with election_strategy=3, 5 MONs across 3 datacenters (wldc, rdc, edc), tiebreaker on rhlocp24
  • Network connectivity verified via ping and nc tests between all monitor pairs
  • Restarting mon.rhlocp24 temporarily resolved the alert (HEALTH_OK), but recurred hours later with 3 partitions detected
  • All MONs on version 19.2.1-366.el9cp with healthy quorum throughout
  • Upstream tracker: https://tracker.ceph.com/issues/71344, Squid backport PR: https://github.com/ceph/ceph/pull/66922
FIX STATUS: Upstream fix exists (tracker#71344). Squid backport PR #66922 is ready to merge but awaiting authority to merge. Workaround: ceph health mute MON_NETSPLIT --sticky. ODF has been using this workaround. No 8.1z fix stream commitment yet.
