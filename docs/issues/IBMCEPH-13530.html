Root Cause Analysis
### Root Cause Analysis:
SUMMARY: Dashboard SMB share form corrupts subvolume group by calling subvol_info with empty subvolume name
ROOT CAUSE: The Ceph dashboard's SMB share creation form has a field that fetches the subvolume path via subvol_info API. Before the user selects a subvolume, the form sends a request with an empty subvolume name: 'ceph fs subvolume info fs "" group'. This empty-name call inadvertently sets the SnapRealm on the subvolume GROUP directory instead of an individual subvolume directory. Once the group directory has SnapRealm set, the MDS rejects subsequent subvolume creation with EINVAL because it detects 'trying to create a subvolume inside another subvolume' (subvol_ino mismatch in handle_client_setvxattr for ceph.dir.subvolume). Existing subvolumes also disappear from the GUI because the corrupted group metadata causes listing failures.
KEY EVIDENCE:
- MDS log: 'subvol ino changed between rdlock release and xlock policylock; subvol_ino: 0x10000000001, cur->ino: 0x100000001fc'
- Dashboard exception: 'Failed to create subvolume testsv2: invalid value specified for ceph.dir.subvolume'
- CLI-only creation works; only dashboard triggers the issue
- Root cause: dashboard calls subvol_info with empty subvol name, corrupting group's SnapRealm
- Fix: UI validation (don't call subvol_info with empty name) + backend validation
FIX STATUS: Fixed. UI fix PR merged. Backend validation fix merged. Downstream MR !1614 for 9.1. Backports created for 9.0z3 and 8.1z6. Verified in 20.2.1-144 by QE (Anushree Hallur). Closed as part of 9.1 release.
Steps to Reproduce
### Steps to Reproduce:
Goal: Reproduce subvolume creation failure via dashboard SMB share form
Environment: IBM Ceph 9.0 (pre-fix)
1. Deploy CephFS, subvolumegroup, subvolume via GUI
2. Deploy SMB cluster using the available CephFS/SVG/subvolume
3. In dashboard, navigate to create a NEW subvolume under the SMB-configured subvolume group
4. Observe: 'invalid value specified for ceph.dir.subvolume' error
5. Existing subvolumes disappear from GUI (still visible via CLI)
DIAGNOSTIC COMMANDS:
- ceph fs subvolume ls <vol> --group-name=<group> (CLI works)
- ceph mgr logs: grep 'invalid value specified for ceph.dir.subvolume'
- ceph tell mds.<fs>:0 dump_ops_in_flight
