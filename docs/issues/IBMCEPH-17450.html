Root Cause Analysis
Race condition in cephadm daemon inventory causes RuntimeError during NFS deprovisioning.
ROOT CAUSE: During NFS daemon deprovisioning, the cephadm module's describe_service() method iterates over the daemon inventory dictionary via cache.get_daemons_with_volatile_status(). Concurrently, the NFS removal thread modifies the same dictionary (removing daemon entries as they are deprovisioned). The dict comprehension at inventory.py:1502 iterates dm.items() while another thread deletes entries from dm, triggering Python's RuntimeError: dictionary changed size during iteration. This crashes the cephadm MGR module, requiring a manual MGR failover to recover. The race is intermittent because it depends on the timing of describe_service() calls overlapping with daemon removal operations.
KEY EVIDENCE
  • Traceback shows RuntimeError at inventory.py:1502 in get_daemons_with_volatile_status() during dict comprehension
  • Crash occurs in describe_service() -> get_daemons_with_volatile_status() path
  • NFS deprovisioning logs show daemon key removal immediately preceding the crash (within same millisecond)
  • Affected version: IBM Ceph 9 (20.1.0-185.0.hotfix.IBMCloud55.el9cp) on IBM Cloud Acadia
  • Workaround confirmed: ceph mgr fail restores service temporarily
  • Related to IBMCEPH-16552
FIX STATUS: PR submitted at https://github.com/ceph/ceph/pull/70897 (posted 2026-08-06). Fix likely involves making a copy of the dictionary before iteration or adding thread-safe locking around the inventory access.
