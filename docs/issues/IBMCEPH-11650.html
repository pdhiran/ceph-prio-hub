Root Cause Analysis
Ceph containers fail to start after node reboot with "Error: could not find cgroup mount in /proc/self/cgroup". Root cause is interaction between podman --cgroups=split mode and certain system configurations.
ROOT CAUSE
  • Cephadm passes --cgroups=split to podman for containerized daemons
  • On some systems, after a reboot, podman cannot find the expected cgroup mount point in /proc/self/cgroup
  • This appears to be triggered by specific combinations of kernel version, systemd version, and podman version -- exact trigger is unknown
  • Multiple customers have hit this (at least 3 separate cases across RHCS 5.3 and later versions)
  • Engineering (Adam King) was unable to identify root cause: "I have never been able to RCA the issue. Given its rarity, it must be something specific with the cgroup setup on the nodes"
  • QE attempted reproduction by switching to cgroups v1 but could not reproduce
WORKAROUND
  • Add --cgroups=enabled to podman run command via extra_container_args in the service spec
  • Or move to cgroups v2: grubby --update-kernel=ALL --args=&quot;systemd.unified_cgroup_hierarchy=1&quot; then reboot
  • Latest comment (Omid Yoosefi, Aug 2026) confirms appending --cgroups=enabled after --cgroups=split fixes the issue
FIX STATUS
  • No permanent fix -- assigned to Aarti Dhikale, moved to 10.0 scope
  • Proposed fix: always append --cgroups=enabled after --cgroups=split in cephadm
  • Cannot reproduce in lab -- environmental issue
