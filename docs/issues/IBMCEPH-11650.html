Root Cause Analysis
Containers fail to start after node reboot with 'could not find cgroup mount in /proc/self/cgroup' due to podman/systemd cgroup interaction bug.
ROOT CAUSE: After a node reboot, podman containers (including MON, OSD) fail to start because the --cgroups=split flag (set by cephadm) does not properly enable cgroup management in certain kernel/podman/systemd version combinations on RHEL 8.10. The exact environmental trigger is unknown -- multiple customers hit this intermittently, and engineering has been unable to reproduce it. The issue appears related to a race condition or state mismatch between podman's cgroup expectations and systemd's cgroup hierarchy after reboot. A fix proposed by IBM Cloud (Acadia) team appends '--cgroups=enabled' after '--cgroups=split' in the podman run command, which resolves the container startup.
KEY EVIDENCE
  • Error: 'could not find cgroup mount in /proc/self/cgroup'
  • Workaround: add --cgroups=enabled to podman run via extra_container_args in service spec
  • Alternative workaround: migrate to cgroups v2 (grubby --update-kernel=ALL --args='systemd.unified_cgroup_hierarchy=1')
  • Multiple customers affected (at least 3 cases), RHEL 8.10 with kernel 4.18.x
  • Issue not reproducible in lab despite attempts to force cgroups v1
  • Acadia team's fix: append '--cgroups=enabled' after '--cgroups=split' in cephadm code
FIX STATUS: Still assigned/open. Not reproducible in lab. Proposed code fix from Acadia team (appending --cgroups=enabled) shared in latest comment. No formal patch merged yet.
