Root Cause Analysis
NFS-Ganesha custom configuration via documented 'ceph nfs cluster config set' does not work -- documentation defect.
ROOT CAUSE: The documented method for customizing NFS-Ganesha configuration using 'ceph nfs cluster config set <cluster> -i <config-file>' writes the custom config to a RADOS object but does NOT override the cephadm-generated /etc/ganesha/ganesha.conf inside the container. The ganesha.conf is regenerated from a Jinja2 template (ganesha.conf.j2) during each deploy/redeploy cycle, ignoring the RADOS-stored custom config for core NFS_CORE_PARAM settings. The working method requires modifying the cephadm template itself via 'ceph config-key set mgr/cephadm/services/nfs/ganesha.conf -i <modified-template>' and then redeploying. QA confirmed the documented steps don't work, but the config-key template override method does work and persists across reboots and upgrades.
KEY EVIDENCE
  • QA verified: 'ceph nfs cluster config set' + 'ceph orch redeploy nfs' does NOT apply changes to ganesha.conf
  • Working workaround: modify ganesha.conf.j2 template -> ceph config-key set mgr/cephadm/services/nfs/ganesha.conf -> redeploy
  • Changes via config-key template persist across reboots, upgrades, and new cluster creation
  • Sachin Punadikar confirmed: documentation defect, valid for 8.1, 9.0, and 9.1
  • Docs updated by Prajesha Naidu: 'Customize an NFS configuration' and 'Remove customized NFS configurations'
FIX STATUS: Modified. Documentation updated for 9.0 release. Updates needed for 8.1 and 9.1 as well. Prajesha Naidu published updated docs.
