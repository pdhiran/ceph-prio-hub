Root Cause Analysis
### Root Cause Analysis:
SUMMARY: RGW fails to start after upgrade from Ceph 7 (Reef) to Ceph 9 (Tentacle) due to undecodable period object
ROOT CAUSE: After a combined OS upgrade (RHEL 9.4→9.7) and Ceph upgrade (7→9), the RGW period epoch .3 stored in .rgw.root pool became undecodable by the new Tentacle RGW code. The customer had previously used an incorrect zone name ('aim-storage0-zone' instead of 'aim-storage-0-zone') which worked under Reef but caused encoding incompatibility under Tentacle. The period data written with the wrong zone name was accepted by Reef but could not be decoded by Tentacle's stricter period deserialization.
KEY EVIDENCE:
- Error: "failed to decode obj from .rgw.root:periods.<id>.3" and "failed to load current period: (5) Input/output error"
- Epoch .2 was readable, epoch .3 (latest_epoch) was not
- Customer admitted zone name discrepancy between setup and actual usage
- All radosgw-admin commands failed with same decode error
FIX STATUS: Fixed in 9.0z2 (build ceph-20.1.0-184). Verified by QE on both multisite and single-site configurations.
