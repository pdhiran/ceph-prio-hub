Root Cause Analysis
RGW SSL certificate upload via Dashboard fails with 500 Internal Server Error on IBM Ceph 9.0z2 due to field naming mismatch introduced by certmgr changes.
ROOT CAUSE
In Ceph 9.0, the cephadm certmgr feature changed the internal key name from ssl_cert to rgw_frontend_ssl_certificate. The Dashboard's service edit flow on 9.0 passes the certificate through ServiceSpec.from_json() which calls validate(). During validation, when ssl=true and ssl_cert is empty (because the Dashboard used the old field name), the code attempts to parse rgw_frontend_ssl_certificate as a combined PEM. If only a certificate OR only a key is provided (not both), parse_combined_pem_file() returns incomplete data, causing SpecValidationError("Failed to parse rgw_frontend_ssl_certificate field."). This is a 9.0-only regression; versions 9.1+ include the CertMgr UI which handles the new field correctly.

FIX STATUS
  • Status: Closed (Done)
  • Fix: Not needed for 9.1+; CertMgr feature in Dashboard handles this correctly from 9.1 onwards
  • Secondary issue: CA trust store not mounted in ceph-mgr container (workaround: mount host CA trust store)
