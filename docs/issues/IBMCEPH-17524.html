Root Cause Analysis
RGW daemon crash loop due to use-after-free in LCOpAction_Transition during lifecycle processing - dangling const& reference to transition_action after orule destruction.
ROOT CAUSE: LCOpAction_CurrentTransition objects hold a const transition_action& transition reference into orule.env.op.transitions map elements. These objects are not deep-copied when picked by the LC workpool threads. When orule gets updated/destroyed during LC processing, the workpool threads still hold dangling references to freed memory, causing use-after-free. tcmalloc detects the invalid allocation attempt and aborts the process. This matches exactly BZ#2416700 fixed upstream by Casey Bodley (commit d1f31bcb3da) - changing const transition_action& transition to transition_action transition (deep copy).
KEY EVIDENCE
  • Customer cluster: 19.2.1-366.el9cp (IBM Ceph 8.1z6), multisite master zone with lifecycle policies
  • GDB shows corrupted transition.storage_class: 'Cannot access memory at address 0x2e312f5054544820'
  • Days field shows garbage: 1969368370 (freed memory pattern)
  • Fix: change const& to value copy in rgw_lc.cc line 1330
  • Cherry-picked into ceph-8.1-rhel-patches as commits 120d52586b and af1f9c16d3
FIX STATUS: Fixed. Available in build ceph-19.2.1-403 (ON_QA for 8.1z8). Fix already present in ceph-9.0+ releases.
