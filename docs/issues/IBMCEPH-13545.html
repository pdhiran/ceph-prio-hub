Root Cause Analysis
NFS-Ganesha fails with DBUS connection error after upgrade from Quincy (17.2) to Reef (18.2) because the upgraded container lacks dbus-daemon socket at /run/dbus/system_bus_socket.
ROOT CAUSE: During upgrade from Ceph Quincy (17.2) to Reef (18.2), the NFS-Ganesha container is restarted with a new container image. The Reef-era NFS-Ganesha (v5.7-2) attempts to initialize DBUS for management interface but fails because the container does not have a running dbus-daemon (no /run/dbus/system_bus_socket). Additionally, the container attempts to register NFSv3 (Protocols = 3,4 in ganesha.conf) which also fails. The combination of DBUS failure and NFSv3 registration failure causes the container to exit. Only one of two NFS daemons fails (the one on the upgraded node), while the other succeeds.
KEY EVIDENCE
  • Error: "gsh_dbus_pkginit :DBUS :CRIT :dbus_bus_get failed (Failed to connect to socket /run/dbus/system_bus_socket: No such file or directory)"
  • Error: "Cannot register NFS V3 on TCP" and "Cannot acquire credentials for principal nfs"
  • Workaround: Remove NFSv3 from ganesha.conf (set Protocols = 4 only) and restart
  • Fix: Ensure dbus socket is available or gracefully degrade without DBUS
FIX STATUS: Fixed. Resolution 'done'. Workaround documented: remove 'Protocols = 3' from ganesha.conf.
