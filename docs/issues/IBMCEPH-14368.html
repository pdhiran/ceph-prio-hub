Root Cause Analysis
OSD.40 crashed with ceph_abort() in build_incremental_map_msg due to BlueStore CRC checksum errors indicating hardware-level data corruption.
ROOT CAUSE: The OSD's BlueStore data on NVMe was corrupted -- blocks that should contain inc_osdmap.306 and osdmap.306 were zeroed out (CRC=0x6706be76 = CRC of all-zeros block). When the OSD attempted to share map epoch 306 during heartbeat, it could not load the incremental or full OSD map from its local store, triggering the panic/abort fallback path at OSD.cc:1484. The abort is expected behavior when neither incremental nor full map can be loaded. Brad Hubbard's analysis confirms this is a hardware issue -- the consistent 0x6706be76 checksum across multiple reads indicates the storage returned zeros where valid data should exist, pointing to NVMe write cache failure or firmware bug.
KEY EVIDENCE
  • 32 CRC errors in crash_dump_log.txt, all with calculated checksum 0x6706be76 (zeros)
  • Crash at OSD.cc:1484 in panic path of build_incremental_map_msg()
  • OSD was only 17 minutes old at crash time
  • No power loss or failure simulation was running
  • Hardware: Samsung MZ1L2960HCJR NVMe SSD on Intel Xeon 6710E
  • Syslog kernel messages showed I/O errors around crash time
FIX STATUS: Not a software bug. Hardware issue on specific NVMe device. OSD marked down, priority lowered. Dev recommends HW investigation/replacement.
