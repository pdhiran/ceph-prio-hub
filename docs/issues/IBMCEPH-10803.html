Root Cause Analysis
RFE to include NFS services in 'ceph status' output -- partially implemented in 9.1 with known limitations.
ROOT CAUSE: Feature request. NFS-Ganesha daemons were not shown in 'ceph -s' output unlike MDS, RGW, etc. Requires both NFS-Ganesha code changes (register_service=true in Ceph FSAL config block) and cephadm changes (template update for ganesha.conf.j2). The NFS-Ganesha side was merged downstream, and the cephadm template changes were merged via MR 1673. However, NFS services only appear in ceph -s after at least one export is created (by design, as Ceph FSAL is only loaded when an export exists). Testing revealed DBUS connection failures in containerized environments.
KEY EVIDENCE
  • NFS-Ganesha PRs on gerrithub (3 candidates under review)
  • Cephadm MR: https://gitlab.cee.redhat.com/ceph/ceph/-/merge_requests/1673 (merged)
  • Limitation: NFS shows in ceph -s only after export creation
  • DBUS errors: 'dbus_bus_get failed' in containerized NFS daemons
  • Related: IBMCEPH-13682 (duplicate)
  • Tested in 9.1 with nfs-ganesha-9.7-0.10.el9cp
FIX STATUS: Partially implemented in 9.1. Blocked by an issue referenced in Harish's last comment. Assigned to Sreedhar Agraharam.
Steps to Reproduce
Goal: Verify NFS services appear in 'ceph status' output after export creation.
Environment: IBM Ceph 9.1 with NFS-Ganesha 9.7+.
  • 1. Deploy NFS cluster -- intent: create NFS service
ceph nfs cluster create test-nfs --placement='count:1'
  • 2. Check ceph -s before export creation -- intent: verify NFS not shown yet

  • 3. Create an NFS export -- intent: trigger Ceph FSAL registration

  • 4. Check ceph -s after export creation -- intent: verify NFS appears
