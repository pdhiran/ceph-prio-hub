Root Cause Analysis
BlueFS::truncate assertion failure (cut_off == p->length) during OSD startup caused by highly fragmented allocations with changing allocation unit sizes.
ROOT CAUSE: During OSD startup, RocksDB attempts to recover log files and triggers a BlueFS::truncate call. When the underlying BlueStore allocations are highly fragmented and the allocation unit size has changed (due to device aging or configuration changes), the truncate logic hits an assertion failure because cut_off does not equal p->length for a given extent. This causes OSD crash loop during the mount phase (OSD::init -> _mount -> RocksDB RecoverLogFiles -> WriteLevel0TableForRecovery -> BlueFS::truncate).
KEY EVIDENCE
  • Assert: 'FAILED ceph_assert(cut_off == p->length)' in BlueFS.cc:3790
  • Stack: OSD::init -> BlueStore::_mount -> RocksDB::RecoverLogFiles -> BlueFS::truncate
