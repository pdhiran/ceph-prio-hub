Root Cause Analysis
Cephadm agent reports TLS connection dropped errors ('peer dropped the TLS connection suddenly, during handshake') after enabling `mgr/cephadm/use_agent`. Likely benign/cosmetic, not impactful.
ROOT CAUSE: After enabling cephadm agent mode (ceph config set mgr mgr/cephadm/use_agent true), the CherryPy-based HTTPS endpoint on the MGR logs INFO-level messages about TLS connection drops during handshake. Engineering (Adam King) assessed these as 'a red herring' -- the TLS drops appear during agent registration and do not indicate functional failure. The separate cephadm ceph-volume JSON decode error (also in the same log snippet) was split to IBMCEPH-13496 as a different issue. Customer ultimately removed the cephadm agent due to unstable behavior.
KEY EVIDENCE
  • Log (INFO level): 'ENGINE Client (...) lost — peer dropped the TLS connection suddenly, during handshake'
  • Reproduced in lab by QE but confirmed as benign by Adam King
  • No functional impact demonstrated; logged at INFO level, not ERROR
  • Customer disabled cephadm agent; no further logs available
FIX STATUS: Closed as 'insufficient data'. No logs from individual failing agents were collected. TLS drops deemed cosmetic/benign.
