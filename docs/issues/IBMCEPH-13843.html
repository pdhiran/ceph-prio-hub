Root Cause Analysis
RGW fails to start after upgrade from Ceph 7 (Reef) to Ceph 9 (Tentacle) because a downstream-only RGWPeriod encoding change removes realm_name, making period objects written by Reef undecodable by Tentacle.
ROOT CAUSE
A downstream-only cherry-pick (commit e79699e7) in ceph-7.1-rhel-patches removed realm_name from the RGWPeriod encoding to resolve rhbz#2196109. This change was cherry-picked from upstream commit 1c579f2, which caused a regression fixed in a follow-up. The regression fix was NOT cherry-picked downstream. As a result, period objects written in the old format (with realm_name) by Reef-era RGW become undecodable after upgrade to Tentacle. The period epoch .3 (latest_epoch) fails to decode, and since RGW requires loading the current period at startup, all radosgw-admin commands and RGW daemons fail with failed to load current period: (5) Input/output error.
KEY EVIDENCE
  • Error: failed to decode obj from .rgw.root:periods.&lt;uuid&gt;.3
  • Period epoch .2 is readable, epoch .3 is not (latest_epoch points to .3)
  • Root cause identified by Casey Bodley: missing regression fix for commit e79699e7
  • Workaround: use Reef-era container to run radosgw-admin period update --commit
  • Fix merged in build ceph-20.2.1-206, verified in 9.1
  • Customer confirmed workaround resolved the issue
FIX STATUS
  • Status: Closed (done)
  • Fixed in IBM Storage Ceph 9.1 (build 20.2.1-206+). Verified with upgrade tests.
