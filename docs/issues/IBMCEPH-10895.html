Root Cause Analysis
NFS-Ganesha container fails to start after host reboot because it starts before the Ceph cluster is fully available, causing RADOS connection failure.
ROOT CAUSE: After a host reboot, the NFS-Ganesha container is started by systemd before the Ceph MON/OSD services are fully available. Ganesha attempts to connect to the RADOS cluster to fetch its configuration from rados://.nfs/<cluster>/conf-nfs.<cluster> and fails with error -107 (transport endpoint not connected). The container then hits a fatal error parsing the config and exits. Systemd's restart logic gives up after rapid restart failures. A secondary issue (BZ#2348763) is that with NFSv3 enabled by default (Protocols = 3,4), ganesha also fails to register NFS V3 on TCP, compounding the startup failure.
KEY EVIDENCE
  • Error: "rados_url_client_setup: Failed to connect to cluster"
  • Error: "Config File (ganesha.conf:36): new url (rados://.nfs/foo/conf-nfs.foo) open error (Unknown error -107)"
  • Error: "Fatal errors. Server exiting..."
  • 100% reproducible: deploy NFS, reboot host, observe container crash loop
  • Fix involved adding retry logic for RADOS connection during ganesha startup
FIX STATUS: Fixed in 8.1z5. Workaround: redeploy ganesha daemon via ceph orch redeploy nfs.<cluster> after reboot, but config reverts to defaults each time.
Steps to Reproduce
Goal: Reproduce NFS-Ganesha container startup failure after host reboot
Environment: IBM Ceph 8.0z2 (19.2.0-98.el9cp) or 8.1 pre-z5
  • 1. Deploy NFS-Ganesha service: ceph orch apply nfs foo --placement=&#x27;1 &lt;hostname&gt;&#x27; -- intent: create NFS service on a single host
  • 2. Wait for NFS daemon to be running: ceph orch ps | grep nfs -- intent: confirm service health
  • 3. Optionally edit ganesha.conf to set Protocols = 4 (remove NFSv3) and restart: ceph orch restart nfs.foo -- intent: work around NFSv3 registration issue
  • 4. Reboot the host running the NFS daemon: ssh root@&lt;host&gt; reboot -- intent: trigger the race condition
  • 5. After reboot, check NFS service status: ceph orch ps | grep nfs -- intent: observe 0/1 running
  • 6. Check journal on the rebooted host: journalctl -u ceph-&lt;fsid&gt;@nfs.&lt;cluster&gt;.&lt;id&gt;.service --no-pager -- intent: see RADOS connection failure
