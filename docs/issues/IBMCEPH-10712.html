Root Cause Analysis
RFE for CRUSH failure domain granularity upgrades -- RESOLVED as implemented in 9.1.
ROOT CAUSE: This was a feature request from Apple for enabling Ceph upgrades at CRUSH bucket granularity (e.g., rack-level parallelism). For 250+ node clusters with 2900+ OSDs, host-level serial upgrade takes ~5 days. The request was for --crush-bucket=rack option on ceph orch upgrade to parallelize upgrades within a CRUSH bucket type. This has been implemented via the crush bucket scoped OSD upgrade functionality delivered through a related ticket.
KEY EVIDENCE
  • Customer: Apple, 250+ node cluster with 2900+ OSDs
  • Resolved by crush bucket scoped OSD upgrade functionality in 9.1
  • Confirmed by Ashwin Joshi (2026-08-04)
  • Related/duplicate: IBMCEPH-11980
FIX STATUS: CLOSED as 'fixed upstream'. Implemented in IBM Ceph 9.1 via ceph orch upgrade start with --crush_bucket_type and --crush_bucket_name options.
