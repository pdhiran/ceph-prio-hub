Root Cause Analysis
Non-leader MON has a log forwarding operation stuck indefinitely in 'forwarded' state, causing persistent SLOW_OPS HEALTH_WARN. Reproducible at 5/5 hit rate on Reef (18.2.1).
ROOT CAUSE: A non-leader MON forwards internal log entries to the leader MON for processing. In some cases, the leader MON never acknowledges the forwarded log entry, leaving the operation stuck in 'forwarded' state indefinitely. The stuck op accumulates age and eventually triggers SLOW_OPS health warning. The operation details show: a log entry forwarded from a non-leader MON (sourced from osd.11) that is never processed by the leader. This occurs during cluster startup or after MDS deployment. Investigation is ongoing.
KEY EVIDENCE
  • Stuck op: 'log(1 entries from seq 2)' in 'forwarded' state for 666+ seconds
  • Op events: initiated -> header_read -> throttled -> all_read -> dispatched -> forward_request_leader -> forwarded (and stays)
  • Reproducible: 5/5 hit rate on Reef (18.2.1-390.el9cp) during CephFS tier-0 test
  • forwarded_to_leader: true but leader never processes it
  • HEALTH_WARN SLOW_OPS persists, cluster never reaches HEALTH_OK
FIX STATUS: In progress. Assigned to Brad Hubbard. Being investigated with MON debug logs from reproduction.
