Root Cause Analysis
Dashboard SMB share form corrupts subvolume group by incorrectly calling subvolume info with empty subvolume name, setting SnapRealm on the group directory instead of subvolume.
ROOT CAUSE: The Dashboard SMB share creation form has a field that retrieves the subvolume path via 'ceph fs subvolume info'. When the subvolume field is empty (before user selects one), the form calls the API with an empty subvolume name: 'ceph fs subvolume info <fs> "" <group>'. This inadvertently sets a SnapRealm on the subvolume GROUP directory (inode 0x10000000001). Subsequent subvolume creation attempts fail because the MDS detects it's trying to create a subvolume inside what it now thinks is already a subvolume (subvol_ino != cur->ino check at handle_client_setvxattr for ceph.dir.subvolume), returning -EINVAL. Existing subvolumes also disappear from the GUI listing because they cannot be enumerated through the corrupted group.
KEY EVIDENCE
  • MDS log: 'subvol ino changed between rdlock release and xlock policylock; subvol_ino: 0x10000000001, cur->ino: 0x100000001fc'
  • Dashboard exception: 'Failed to create subvolume testsv2: invalid value specified for ceph.dir.subvolume'
  • CLI-only workflow does NOT exhibit the bug (SnapRealm set correctly on subvolume dir)
  • Dashboard sets SnapRealm on group directory during SMB share form load
  • Fix: UI validation to prevent empty subvolume name in API call + backend validation
FIX STATUS: Fixed in 8.1z6 (19.2.1-355.el9cp). UI fix prevents empty subvolume name call. Backend fix adds validation. Verified by QE.
Steps to Reproduce
Goal: Verify subvolume creation works under SMB-configured subvolume group after fix
Environment: IBM Ceph 8.1z6+ with Dashboard and SMB enabled
  • 1. ceph fs volume create cephfs -- intent: create filesystem
  • 2. Create subvolumegroup and subvolume via Dashboard -- intent: baseline
  • 3. Configure SMB cluster and share via Dashboard using the subvolume -- intent: trigger the condition
  • 4. Create a NEW subvolume under the same subvolumegroup via Dashboard -- intent: verify no error
  • 5. Verify subvolumes are visible in GUI and CLI -- intent: confirm no corruption
