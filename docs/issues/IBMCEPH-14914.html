Root Cause Analysis
RFE for dynamically scalable RGW endpoints with auto-scaling between min/max counts during burst workloads.
ROOT CAUSE: This is a feature request. A customer performs large monthly application backups to S3 buckets, overwhelming the fixed number of RGW endpoints and requiring restarts. The request is for the ability to dynamically scale RGW endpoints (and the ingress service) between predefined min/max counts, similar to NooBaa's autoscaling endpoint feature in ODF. This would help during periodic burst ingestion without permanent over-provisioning.
KEY EVIDENCE
  • Customer scenario: monthly backup cripples RGW endpoints
  • Current workaround: manual ingress service setup + RGW scaling
  • Reference: RHODF 4.18 NooBaa endpoint autoscaling
  • Targeted to Backlog
  • Assigned to Matthew Benjamin (RGW lead)
FIX STATUS: RFE status is 'new'. Bipin Kunal asked L3 team to review (2026-08-06). No implementation or design work started.
