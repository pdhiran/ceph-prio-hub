Root Cause Analysis
SSE-S3 encryption with Vault KV secret engine returns HTTP 400 because only transit engine is supported for SSE-S3.
ROOT CAUSE: The RGW source code (rgw_kms.cc) functions create_bucket_key and remove_sse_s3_bucket_key only support the Vault transit secret engine. When KV is configured, both functions fall through to the else branch and return -EINVAL with 'Missing or invalid secret engine' without contacting Vault. This is by design: SSE-S3 requires the RGW to generate and manage keys dynamically (which transit supports), while KV only stores pre-existing keys (appropriate for SSE-KMS where the client supplies the key ID). The IBM documentation incorrectly suggests KV works for SSE-S3.
KEY EVIDENCE
  • Version: 19.2.0-98.el9cp (IBM Ceph 8.0)
  • Marcus Watts (engineer) confirmed: 'SSE-s3 only supports transit and it would not make sense to support kv'
  • SSE-KMS originally only supported KV; transit added later as recommended choice
  • KV is only kept for existing SSE-KMS deployments
  • Documentation needs correction
FIX STATUS: Not a bug -- by design. Documentation should be updated to clarify SSE-S3 only supports transit engine. Workaround: use transit secret engine for SSE-S3.
