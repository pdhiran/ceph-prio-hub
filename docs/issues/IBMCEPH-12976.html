Root Cause Analysis
'cephadm shell --name nfs.<id>' fails with 'pool missing from dict' because NFSGanesha constructor requires pool config that's only available during deployment.
ROOT CAUSE: When cephadm shell --name is used with an NFS daemon, cephadm must resolve container mounts by constructing an NFSGanesha object. During deployment, the manager provides config_blobs (including 'pool' and 'files'). During cephadm shell invocation, neither config_blobs nor config_json is available, so fetch_configs() returns {}. NFSGanesha.__init__() calls dict_get(config_json, 'pool', require=True), which fails immediately on the empty dict. The fix: (1) Remove require=True from pool lookup in __init__, (2) Move pool validation to validate() with a check that skips content validation when config_json is empty (the shell path).
KEY EVIDENCE
  • Error: 'cephadmlib.exceptions.Error: pool missing from dict'
  • Traceback: data_utils.py:39 dict_get -> nfs.py:57 __init__
  • Workaround: use container ID or full container name instead of daemon type.ID
  • Reproducible on Ceph 8 (19.2.1-292) and Ceph 9 (20.1.0-146)
  • Works with other daemons (osd, mon, mgr) because they use Ceph.get_ceph_mounts()
  • Full RCA and fix provided by Aarti Dhikale with working test results
