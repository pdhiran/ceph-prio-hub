Root Cause Analysis
`ceph orch upgrade ls` fails with 400 Bad Request because cephadm's registry token parser doesn't strip whitespace from WWW-Authenticate header parameters returned by IBM Container Registry.
ROOT CAUSE
IBM Container Registry (cp.icr.io) returns WWW-Authenticate headers with spaces after commas: Bearer realm="https://cp.icr.io/oauth/token", service="registry", scope="repository:cp/ibm-ceph/ceph-8-rhel9:pull". The current registry.py:get_token() implementation splits the header by comma but doesn't call .strip() on the resulting key-value pairs. This produces parameter keys with leading spaces ( service, scope) which create malformed OAuth token request URLs, resulting in HTTP 400 from the registry.
KEY EVIDENCE
  • Error: 400 Client Error: Bad Request for url: https://cp.icr.io/oauth/token?service=registry&amp;scope=...
