Root Cause Analysis
Missing 'operator-requested' log message during user-initiated scrub in Ceph 8.x -- logging difference, not functional bug.
ROOT CAUSE: The 'operator-requested' log tag was introduced in Ceph 9.x via the new SchedEntry system (commit 2b6e1dd90b73bf1db16f9ee1b7ad519be3ca97ba) and was never backported to Ceph 8.x (Squid). In 8.x, user-initiated scrubs use the 'req_scrub' flag internally but do not emit the 'operator-requested' string in PG state logs. The scrub functionality itself works correctly in both versions -- only the logging/state label differs. The original reporter also had confusion about expected log messages for scrub_load_below_threshold when threshold is set to 0 (should produce '= no', not '= yes').
KEY EVIDENCE
  • Ceph 9.x OSD log: 'active+clean+scrubbing(operator-requested)' present
  • Ceph 8.x OSD log: grep for 'operator-requested' returns empty
  • Timothy Nguyen confirmed: code for 'operator-requested' only exists in 9.x SchedEntry
  • Assignee recommends CephCI script update to check for both 'operator-requested' (9.x) and 'req_scrub' (8.x)
  • CephCI automation script has inconsistencies: Case 5 checks for 'scrub_load_below_threshold:.* = yes' with threshold=0 (logically should be '= no')
FIX STATUS: Assigned to Timothy Nguyen. No code fix needed -- this is a test/automation script update. CephCI scripts should look for 'req_scrub' on 8.x and 'operator-requested' on 9.x.
