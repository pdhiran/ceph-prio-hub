Root Cause Analysis
`ceph pg <pgid> query` command throws Python JSONDecodeError when the pool's EIO flag is set, because the OSD returns an empty/error response that the CLI cannot parse.
ROOT CAUSE: When the EIO (Error I/O) flag is enabled on a pool via ceph osd pool set <pool> eio true, the OSD returns an error (EIO) for PG query operations on PGs belonging to that pool. The ceph CLI tool expects a valid JSON response from pg query, but the OSD returns either an empty response or a non-JSON error when the EIO flag intercepts the operation. The Python JSON parser in /usr/bin/ceph (specifically parse_json_funcsigs in ceph_argparse.py) then fails with JSONDecodeError: Expecting value: line 1 column 1 (char 0) because it receives an empty string. The issue is that the OSD-side PG query handler does not properly handle the EIO pool flag — it should either return a valid JSON error response or the CLI should gracefully handle the error return code.

Steps to Reproduce
Goal: Reproduce JSONDecodeError when running ceph pg query on a pool with EIO flag enabled.
Environment: IBM Ceph 8.1 or 9.x (any version — issue spans all versions since 7.0).
  • 1. Deploy a Ceph cluster -- intent: get a running cluster
  • 2. Create a pool:
ceph osd pool create test-eio-pool 32
-- intent: have a pool to set EIO on
  • 3. Run pg query on any PG of the pool (should succeed):
ceph pg <pool-pg-id> query
-- intent: verify baseline works
  • 4. Enable EIO flag on the pool:
ceph osd pool set test-eio-pool eio true
-- intent: trigger the bug condition
  • 5. Re-run pg query on the same PG:
ceph pg <pool-pg-id> query
-- intent: this should throw JSONDecodeError
  • 6. Verify: Python traceback with 'JSONDecodeError: Expecting value: line 1 column 1 (char 0)'
  • 7. Disable EIO and verify pg query works again:
ceph osd pool set test-eio-pool eio false
ceph pg <pool-pg-id> query
