Root Cause Analysis
OOM kills during Ceph 5.3 to 7.1z8 upgrade traced to Intel ICE network driver kernel memory leak, not Ceph.
ROOT CAUSE: The memory growth was initially attributed to Ceph OSD memory leak but investigation proved OSD memory consumption was within expected limits (7-10GB per OSD, within 8GB target). The actual root cause was a memory leak in the Intel ICE network driver on kernel 5.14.0-611.27.1.el9_7. Page_owner data confirmed ~30GB allocated via ICE driver paths out of 155GB total. The issue was exposed during the Ceph 5.3 to 7.1z8 upgrade because the OS was simultaneously upgraded from RHEL 8 to RHEL 9.7 (which changed cgroup accounting from v1 to v2). Under cgroup v2, kernel buffers from bluefs_buffered_io fall outside cgroup memory accounting, preventing proper memory pressure detection.
KEY EVIDENCE
  • OSD memory per process: 7-10GB (within osd_memory_target=8GB)
  • Total system memory: 263GB, used: 252GB, free: 3.2GB
  • Page_owner: ~30GB allocated via ICE driver, ~94GB via ceph daemon processes (mostly rocksdb)
  • Fix: kernel downgrade to 5.14.0-611.7.1.el9_7 stabilized memory at 27-34%
  • Related to previously fixed ICE driver bug in kernel-5.14.0-563.el9 (9.6)
FIX STATUS: Closed. Root cause: Intel ICE driver kernel memory leak on specific RHEL 9.7 kernel. Workaround: downgrade to kernel-5.14.0-611.7.1.el9_7. Permanent fix expected from Red Hat kernel team.
